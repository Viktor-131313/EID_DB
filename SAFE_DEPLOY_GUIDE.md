# 🛡️ БЕЗОПАСНЫЙ ПРОЦЕСС ДЕПЛОЯ

## ⚠️ ВАЖНО: Всегда следуйте этому процессу!

### Шаг 1: Скачайте данные с продакшена ПЕРЕД любыми изменениями

```bash
cd ID
node scripts/download-production-data.js
```

**Проверьте вывод** - должны увидеть:
```
✓ Сохранено: objects.json
✓ Сохранено: tasks.json
✓ Сохранено: snapshots.json
```

### Шаг 2: Проверьте данные (опционально, но рекомендуется)

```bash
node scripts/pre-commit-check.js
```

Этот скрипт проверит, что файлы не пустые и не только тестовые.

### Шаг 3: Закоммитьте данные ОТДЕЛЬНО от кода

```bash
cd ID

# Добавьте ТОЛЬКО данные
git add backend/data/*.json

# Закоммитьте с понятным сообщением
git commit -m "Backup: Данные с продакшена $(Get-Date -Format 'yyyy-MM-dd HH:mm')"

# Запушьте
git push
```

**ВАЖНО:** Делайте отдельный коммит для данных, не смешивайте с изменениями кода!

### Шаг 4: Теперь можно деплоить изменения кода

После того как данные закоммичены и запушены, можно безопасно:

1. Вносить изменения в код
2. Коммитить изменения кода
3. Пушить в репозиторий
4. Render автоматически задеплоит, и данные сохранятся (они уже в репозитории)

---

## 📋 Чеклист перед каждым деплоем:

- [ ] Скачал данные с продакшена: `node scripts/download-production-data.js`
- [ ] Проверил, что файлы скачались (проверил размеры файлов)
- [ ] Закоммитил данные отдельно: `git commit -m "Backup: Данные с продакшена"`
- [ ] Запушил данные: `git push`
- [ ] Только потом вношу изменения в код
- [ ] Коммичу и пушу изменения кода

---

## 🔄 Если нужно обновить данные ПОСЛЕ работы на продакшене:

1. Работаете на продакшене через интерфейс (добавляете объекты, задачи и т.д.)
2. **СРАЗУ после работы** скачайте данные:
   ```bash
   node scripts/download-production-data.js
   ```
3. Проверьте файлы
4. Закоммитьте и запушьте:
   ```bash
   git add backend/data/*.json
   git commit -m "Backup: Обновленные данные с продакшена"
   git push
   ```

---

## ❌ ЧТО НИКОГДА НЕ ДЕЛАТЬ:

- ❌ НЕ коммитить код и данные вместе в одном коммите
- ❌ НЕ деплоить без предварительного скачивания данных
- ❌ НЕ игнорировать предупреждения скрипта проверки
- ❌ НЕ пушить изменения, если не уверены в данных

---

## 💡 Дополнительные советы:

1. **Делайте git tags** для важных версий с данными:
   ```bash
   git tag -a v1.0-data-backup -m "Версия с актуальными данными"
   git push --tags
   ```

2. **Периодически проверяйте** размеры файлов данных - они должны расти

3. **Если сомневаетесь** - лучше лишний раз скачать данные, чем потерять их
