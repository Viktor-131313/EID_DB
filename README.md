# Praktis ID Dashboard

Дашборд для мониторинга внедрения электронной исполнительной документации Praktis ID на пилотных объектах.

## 📋 Описание проекта

Веб-приложение для отслеживания прогресса согласования актов исполнительной документации на различных объектах. Система позволяет группировать объекты по контейнерам, отслеживать статистику по каждому контейнеру, сравнивать статистику между планерками и управлять задачами разработки.

## 🎯 Основные возможности

### 🔐 Система аутентификации

- **Режим просмотра (View-only)**: По умолчанию приложение открывается в режиме просмотра
  - Просмотр всех данных, экспорт в PDF
  - Открытие объектов в режиме просмотра
  - Развертывание статистики и сравнение планерок
  - **Без возможности редактирования, добавления или удаления данных**
- **Авторизация**: Клик по favicon (логотип) в хедере открывает модальное окно входа
  - Логин: `admin`
  - Пароль: `Admin2026!`
  - После авторизации доступны все функции редактирования
  - В хедере появляется кнопка "Выйти" для выхода из системы

### Управление контейнерами объектов

- **Создание контейнеров**: Нажмите клавишу `Insert` для создания нового контейнера (только для авторизованных пользователей)
- **Переименование заголовка**: Двойной клик по заголовку "Объекты" позволяет переименовать его (например, "Объекты Сетл")
- **Переименование контейнеров**: Двойной клик по названию контейнера открывает режим редактирования (только для авторизованных пользователей)
- **Перемещение контейнеров**: Кнопки "↑" и "↓" слева от каждого контейнера позволяют изменить порядок отображения (только для авторизованных пользователей)
  - Кнопки автоматически отключаются, если контейнер уже первый или последний
  - Порядок сохраняется в базе данных и восстанавливается при перезагрузке

### Управление объектами

- **Добавление объектов**: Кнопка "Добавить объект" находится в каждом контейнере (только для авторизованных пользователей)
- **Просмотр объектов**: Клик по карточке объекта открывает детальное модальное окно (доступно в режиме просмотра)
- **Редактирование объектов**: В модальном окне можно редактировать все данные объекта (только для авторизованных пользователей)
- **Удаление объектов**: Доступно в модальном окне редактирования (только для авторизованных пользователей)
- **Фото объектов**: Возможность загрузить JPEG или PNG фото объекта (отображается на карточке над названием)
  - Фото увеличивает высоту карточки, но не ширину
  - Фото сохраняется в base64 формате
  - **Редактирование фото**: Для админов доступны кнопки "Изменить фото" и "Удалить фото" с кастомными подсказками
- **Статус объекта**: Отображается на карточке с черной рамкой и подписью "Статус:"
- **Метрики исполнительности**: На карточках объектов отображаются:
  - Процент готовности актов (готовность = сгенерировано / должно быть из Айконы)
  - Отставание (сколько актов еще нужно сгенерировать)
  - Визуальные индикаторы: зеленый (хорошо), желтый (требует внимания), красный (критично)
  - Значок критического объекта (пульсирующая красная иконка) для объектов с готовностью < 70%

### Структура данных объекта

Каждый объект содержит:

1. **Название объекта** - основное название
2. **Очередь** - номер очереди объекта (опционально)
3. **Фото объекта** - JPEG или PNG изображение (опционально)
4. **Статус** - краткий текстовый статус объекта (отображается на карточке с черной рамкой)
5. **ID объекта в Айконе** - идентификатор для синхронизации с внешней системой (только для админов)

#### 🏗️ Иерархическая структура объектов (Новое)

Объекты теперь имеют многоуровневую структуру:

- **Объект** → **Корпуса** → **Секции** → **Подрядчики** → **СТК (СМР)**

**Корпуса (Buildings):**
- У объекта может быть несколько корпусов (например, "1", "2", "8.2")
- Каждый корпус имеет уникальное название
- Корпуса отображаются в виде карточек, клик по карточке открывает секции

**Секции (Sections):**
- Каждый корпус может содержать несколько секций (например, "1", "2", "3")
- Секции отображаются в выпадающем списке при выборе корпуса
- При выборе секции отображаются подрядчики, работающие в этой секции

**Подрядчики (Contractors):**
- Каждая секция может содержать несколько подрядчиков
- У каждого подрядчика есть:
  - Название подрядчика
  - Вид работ (например, "Кладка", "ОВ и ВК")
  - Список СТК (СМР) с актами
  - Статистика по актам (сгенерировано, отправлено, согласовано, отклонено, подписано)

**СТК (СМР) - Виды работ:**
- Каждый подрядчик имеет список СТК
- Каждый СТК содержит:
  - Название СТК
  - **PRAKTIS ID** - количество фактически сгенерированных актов (заполняется вручную или из другого веб-интерфейса)
  - **СЗ ICONA** - количество этажей с SZCompletion = 100% (синхронизируется из Aikona API)
  - Статистика по другим типам актов (отправлено, согласовано, отклонено, подписано)

#### Модальное окно выбора подрядчика

При клике на карточку объекта открывается промежуточное модальное окно (`ContractorSelectionModal`):

- **Редактирование объекта** (только для админов):
  - Название объекта
  - Очередь
  - Статус
  - ID объекта в Айконе
  - Фото объекта (загрузка, изменение, удаление)
  - Кнопка "Забрать данные" для синхронизации с Aikona API

- **Управление корпусами**:
  - Список корпусов в виде карточек
  - Клик по карточке корпуса открывает его секции
  - Добавление/удаление корпусов (только для админов)
  - Визуальные маркеры отставания (красная рамка) для корпусов с проблемами

- **Управление секциями**:
  - Выпадающий список для выбора корпуса
  - При выборе корпуса отображаются его секции
  - Добавление/удаление секций (только для админов)
  - Секции с подрядчиками скрыты по умолчанию, появляются при выборе секции

- **Управление подрядчиками**:
  - Список подрядчиков в выбранной секции
  - Добавление/удаление подрядчиков (только для админов)
  - Клик по подрядчику открывает детальное модальное окно (`ContractorModal`)
  - Отображение статистики и маркеров отставания

- **Общая статистика по объекту**:
  - Суммарная статистика по всем подрядчикам всех секций всех корпусов
  - Сгенерировано, отправлено, согласовано, отклонено, подписано

- **Детали отставания**:
  - Карточка с детальной информацией об отставании
  - Показывает по каким корпусам, секциям и подрядчикам есть отставание
  - Визуальные маркеры на карточках корпусов и подрядчиков

#### Модальное окно подрядчика

При клике на подрядчика открывается детальное модальное окно (`ContractorModal`):

- **Информация о подрядчике**:
  - Название подрядчика
  - Вид работ
  - Корпус и секция (отображаются в виде бейджей)

- **Управление СТК (СМР)**:
  - Секция "Сгенерированных актов" с таблицей:
    - Столбец "СМР" - название вида работ
    - Столбец "PRAKTIS ID" - инпут для ввода фактически сгенерированных актов (фиксированная ширина 80px, выровнен по правому краю)
    - Разделитель "из"
    - Столбец "СЗ ICONA" - количество из Aikona API (фиксированная ширина 80px, выровнен по правому краю)
  - Двойной клик по СМР позволяет переименовать
  - Нажатие Delete удаляет СМР (с кастомным подтверждением)
  - Кнопка "+ Добавить СМР" создает новый СМР
  - Секции "Отправлено", "Согласовано", "Отклонено", "Подписано" с аналогичной структурой

- **Блокирующие факторы**:
  - Список сотрудников, требующих вовлечения руководства

### Статистика

- **Общая статистика**: Отображается вверху страницы, считает все объекты из всех контейнеров
  - Всего объектов
  - Сгенерировано актов
  - Отправлено на согласование
  - Согласовано (с процентом от отправленных)
  - Отклонено (с процентом от отправленных)
  - **Подписано** (с процентом от согласованных) ✨

- **Статистика контейнера**: Раскрывается кнопкой "Показать статистику" в заголовке каждого контейнера
  - Те же метрики, что и в общей статистике
  - Считает только объекты конкретного контейнера
  - **Процент сгенерированных**: Рассчитывается как процент сгенерированных актов от общего количества объектов

### Аналитика исполнительности и система алертов

- **Метрики на карточках объектов**:
  - **Процент готовности актов**: Рассчитывается как (сгенерировано / должно быть из Айконы) × 100%
  - **Отставание**: Количество актов, которые еще нужно сгенерировать
  - **Визуальные индикаторы статуса**:
    - 🟢 Зеленый (Хорошо): готовность ≥ 85%
    - 🟡 Желтый (Требует внимания): готовность 70-84%
    - 🔴 Красный (Критично): готовность < 70%
  - **Значок критического объекта**: Пульсирующая красная иконка для объектов с готовностью < 70%

- **Панель "Проблемы"**: Кнопка в хедере Dashboard (показывается только при наличии критических объектов)
  - Отображает количество критических объектов
  - При клике открывается модальное окно со списком проблемных объектов
  - Для каждого объекта показывается: название, контейнер, процент готовности, отставание
  - Клик по объекту в панели:
    - Закрывает панель проблем
    - Открывает модальное окно объекта
    - Автоматически раскрывает секцию "Сгенерированных актов"
    - Подсвечивает проблемную секцию (красная рамка, пульсирующая анимация)
    - Прокручивает к проблемной секции

### Статистика планерок

- **Создание снимков**: Ручное создание снимка текущего состояния для отслеживания изменений (только для авторизованных пользователей)
  - Кастомное модальное окно подтверждения перед созданием
  - Уведомление об успешном создании (автоматически исчезает через 3 секунды)
- **Сравнение статистики**: Сравнение текущего состояния с предыдущими планерками (доступно в режиме просмотра)
- **Визуализация**: График с отображением изменений (абсолютные значения и дельты)
  - Все цифры в диаграмме отображаются черным цветом
- **Фильтрация метрик**: Чекбоксы для выбора отображаемых типов актов
- **Таблица изменений**: Детальная таблица изменений по контейнерам и объектам
  - **Строка итогов**: Внизу таблицы отображается общая сумма изменений по каждому столбцу
  - Итоги отображаются как в веб-интерфейсе, так и в PDF экспорте
- **Выбор периода**: Возможность выбрать любую предыдущую планерку для сравнения
- **Отображение времени**: Дата и время создания снимка отображаются в графике
- **Удаление снимков**: Возможность удалить сохраненный снимок (только для авторизованных пользователей)
  - Кастомное модальное окно подтверждения с указанием даты снимка
  - Уведомление об успешном удалении

### 📄 Экспорт в PDF

- **Кнопка экспорта**: Кнопка "Экспорт в PDF" в хедере дашборда
- **Индикатор прогресса**: При экспорте отображается кастомное модальное окно с прогрессом генерации
  - Формат: "Идет генерация PDF X из Y..." (X - номер уже сгенерированной страницы)
  - Анимированные точки для визуализации процесса
  - Страницы скрыты от пользователя во время генерации
- **Титульная страница**: Первая страница PDF содержит изображение `PDF_first_list.png` с текущей датой в правом нижнем углу
- **Вторая страница**: 
  - Заголовок "Praktis ID"
  - Общая статистика (SummaryCards)
  - Статистика планерок (сравнение, графики, легенда с чекбоксами, изменения по контейнерам)
  - Все цифры в диаграмме отображаются черным цветом
  - Строка итогов в таблице изменений по контейнерам
  - Без сохраненных снимков статистики
- **Страницы объектов**: Каждый контейнер объектов выводится на отдельной странице
  - Плитки объектов одинакового размера на всех страницах
  - Фото объектов отображаются на плитках
  - Статус объекта с черной рамкой и подписью "Статус:"
- **Страницы задач**: Таблица "Задачи для разработчиков" занимает почти всю ширину страницы
  - 16 строк на странице, остальные переносятся на следующие страницы
  - Заголовки столбцов правильно выровнены над колонками
  - Заголовки "Дата обнаружения", "Статус", "Планируется устранить", "Критичность" выровнены по правому краю
  - Таблица автоматически переносится на следующие страницы при большом количестве строк

### Задачи для разработки

- **Управление задачами**: Таблица с задачами разработки
- **Свернутое состояние по умолчанию**: Секция задач по умолчанию свернута на веб-интерфейсе (кнопка развернуть/свернуть)
  - При экспорте в PDF все задачи всегда полностью развернуты
- **Структура задачи**:
  - ID (DEV-номер) - буквы "DEV-" фиксированы, вводится только номер
  - Описание задачи
  - Дата обнаружения (календарь)
  - Статус: To Do, In Progress, Review, Done
  - Планируемая дата исправления (месяц и год, опционально)
  - **Критичность**: Уровень важности задачи
    - ⚠️ **Критично** (красный) - критически важные задачи
    - ⚡ **Некритично** (желтый) - некритичные задачи
    - 💡 **Пожелания от пользователей** (зеленый) - запросы пользователей
  - **Ссылка на таск-менеджер**: Опциональное поле для ссылки на задачу в внешней системе
    - Отображается кнопкой со стрелкой в столбце "Действия"
    - Кнопка видна всем пользователям (не только админам)
    - Открывает ссылку в новой вкладке
- **Сортировка по критичности**: Задачи автоматически сортируются по уровню критичности (критичные → некритичные → пожелания)
- **Inline редактирование**: 
  - Статус, планируемая дата и критичность редактируются прямо в таблице (клик по ячейке) - только для авторизованных пользователей
- **Фильтрация**: По статусу и месяцу обнаружения
- **Удаление**: Через кнопку или клавишу Delete (с кастомным модальным окном подтверждения, только для авторизованных пользователей)
- **Добавление задач**: Кнопка "Добавить задачу" (только для авторизованных пользователей)

## 🏗️ Технологический стек

### Backend
- **Node.js** с **Express.js**
- **PostgreSQL** база данных (опционально, если установлена переменная `DATABASE_URL`)
- Гибридное хранение данных: PostgreSQL или JSON файлы (автоматическое определение)
- RESTful API
- CORS для работы с фронтендом
- Раздача статических файлов React в production
- **Интеграция с Aikona API**: Автоматическая синхронизация данных о выполненных работах
  - Ежедневная синхронизация в 7:00 (МСК) через cron job
  - Ручная синхронизация через кнопку "Забрать данные"
  - Логирование результатов синхронизации

### Frontend
- **React 18**
- Компонентная архитектура
- Axios для HTTP запросов
- Font Awesome для иконок
- CSS для стилизации (включая кастомные графики)
- **Адаптивная верстка**: Поддержка различных разрешений экранов
  - Мобильные устройства: 360px (оптимизированы плитки, убраны лишние отступы, скрыты кнопки перемещения контейнеров)
  - Планшеты: 768px
  - Десктопы: 1040px, 1366px, 1920px
- **Кастомные модальные окна**: Замена стандартных `alert` и `confirm` на стилизованные компоненты
  - `ConfirmModal` - для подтверждений действий
  - `ToastNotification` - для уведомлений (автоматически исчезают через 3 секунды)
- **Кастомные tooltips**: Все подсказки используют единый стиль
  - Белый текст на черном фоне
  - Закругленные края
  - Плавная анимация появления
  - Поддержка различных позиций (сверху, снизу, справа, слева)
  - Tooltips для кнопок фото отображаются снизу, чтобы не обрезаться контейнером

## 📡 API Endpoints

### Контейнеры

- `GET /api/containers` - Получить все контейнеры (сортировка по `display_order`)
- `POST /api/containers` - Создать новый контейнер
- `PUT /api/containers/:containerId` - Обновить контейнер (переименовать)
- `POST /api/containers/:containerId/move` - Переместить контейнер вверх или вниз (`direction: 'up' | 'down'`)
- `DELETE /api/containers/:containerId` - Удалить контейнер
- `GET /api/containers/:containerId/stats` - Получить статистику контейнера

### Объекты в контейнерах

- `GET /api/containers/:containerId/objects` - Получить объекты контейнера
- `POST /api/containers/:containerId/objects` - Создать объект в контейнере
- `PUT /api/containers/:containerId/objects/:objectId` - Обновить объект
- `DELETE /api/containers/:containerId/objects/:objectId` - Удалить объект
- `POST /api/containers/:containerId/objects/:objectId/sync-aikona` - Синхронизировать данные объекта из Aikona API

### Статистика

- `GET /api/stats` - Получить общую статистику по всем контейнерам
- `GET /api/health` - Проверка здоровья сервера

### Снимки статистики (Snapshots)

- `GET /api/snapshots` - Получить все снимки
- `POST /api/snapshots` - Создать новый снимок текущего состояния
- `GET /api/snapshots/latest/compare` - Сравнить текущее состояние с последним снимком
- `GET /api/snapshots/compare/:snapshotId` - Сравнить текущее состояние с указанным снимком

### Задачи разработки (Tasks)

- `GET /api/tasks` - Получить все задачи
- `POST /api/tasks` - Создать новую задачу
- `PUT /api/tasks/:taskId` - Обновить задачу
- `DELETE /api/tasks/:taskId` - Удалить задачу

### Интеграция с Aikona API

- `GET /api/aikona-sync-log` - Получить последний лог синхронизации с Aikona

## 🔧 Особенности реализации

### Миграция данных

Система автоматически мигрирует старые данные (если они были в формате массива объектов) в новый формат с контейнерами.

### Валидация данных

- Количество отправленных на согласование актов не может превышать количество сгенерированных
- Сумма согласованных и отклоненных актов не может превышать количество отправленных на согласование
- Подписанных актов не может быть больше согласованных
- Валидация выполняется как на клиенте, так и на сервере

### Расчет процентов

Проценты рассчитываются автоматически:
- Отправлено % = (sentForApproval / generatedActs) × 100
- Согласовано % = (approvedActs / sentForApproval) × 100
- Отклонено % = (rejectedActs / sentForApproval) × 100
- Подписано % = (signedActs / approvedActs) × 100

### Синхронизация СМР

При добавлении нового СМР в секцию "Сгенерированных актов", он автоматически добавляется во все остальные секции (отправлено, согласовано, отклонено, подписано). Переименование СМР также синхронизируется между всеми секциями.

## 🔗 Интеграция с Aikona API

Система поддерживает автоматическую синхронизацию данных о выполненных работах из внешней системы Aikona.

**Настройка:**
1. В карточке объекта введите "ID объекта в Айконе" (например, 401)
2. Нажмите кнопку "Забрать данные" для ручной синхронизации
3. Система автоматически найдет соответствующие СМР по названию и обновит поле "СЗ Icona" (общее количество)

**Автоматическая синхронизация:**
- Ежедневная синхронизация в 7:00 (МСК) через cron job
- Логирование результатов синхронизации
- Уведомления для админов через кнопку "Лог синхронизации" в хедере

**API Aikona:**
- Endpoint: `https://icona.setl.ru/rest_api/api/IntegrationObjectInfo`
- API Key: `f48941fd-ab51-4edd-b1f2-f202597c9920` (хранится в переменной окружения `AIKONA_API_KEY`)
- Логика синхронизации:
  1. Запрос данных объекта по `ObjectId` из Aikona API
  2. Парсинг ответа: извлечение массива `STKs` (СТК)
  3. Для каждого СТК у подрядчика:
     - Поиск соответствующего СТК в ответе Aikona по названию (нормализация, игнорирование регистра)
     - Парсинг `LocationName` для извлечения корпуса и секции (формат: "Корпус 8.2_Секция 2_Этаж 4")
     - Фильтрация локаций по корпусу и секции подрядчика
     - Подсчет этажей с `SZCompletion === 100` для данной комбинации
  4. Обновление только поля `total` (СЗ ICONA) - количество этажей с SZCompletion = 100%
  5. Поле `count` (PRAKTIS ID) не обновляется - заполняется вручную или из другого веб-интерфейса
- Таймаут запроса: 180 секунд (3 минуты) для больших ответов
- Механизм повторов: до 3 попыток при ошибках соединения

## 🔔 Система напоминаний о несогласованных актах (Планируется)

> **Статус**: В разработке (ожидание API Практис ID)  
> Подробное описание системы: [`ACT_REMINDER_SYSTEM.md`](ACT_REMINDER_SYSTEM.md)

### Шаблоны сообщений для автоматических напоминаний

Система будет отправлять автоматические напоминания в три этапа:

#### Тип 1: Ответственному пользователю

**Тема письма**: `Требуется ваше действие на платформе Praktis ID`

**Текст сообщения**:

```
Добрый день, [Имя Отчество пользователя]!

Напоминаем вам, что на платформе Praktis ID ожидают вашего внимания документы (акты), 
требующие рассмотрения и согласования.

Пожалуйста, зайдите на платформу в течение ближайших 24 часов для выполнения 
необходимых действий.

Обращаем ваше внимание, что через 48 часов с момента данного уведомления автоматическое 
оповещение будет направлено вашему непосредственному руководителю, 
[Имя Отчество руководителя, должность].

Данное сообщение сформировано и отправлено автоматически. Ответ на него не требуется.
```

**Условия отправки**: 
- Акты находятся на согласовании более 24 часов
- За последние 24 часа не было действий с актами

---

#### Тип 2: Непосредственному руководителю

**Тема письма**: `Информация о действиях подчинённого на платформе Praktis ID`

**Текст сообщения**:

```
Добрый день, [Имя Отчество руководителя]!

Информируем вас, что ваш сотрудник, [Имя Отчество сотрудника, должность], 
на текущий момент не выполнил необходимые действия по рассмотрению и согласованию 
актов на платформе Praktis ID. Документы поступили ему [дата и время поступления].

Пожалуйста, примите, по возможности, меры для ускорения процесса согласования.

Для сведения: через 24 часа система автоматически проинформирует об этой ситуации 
вышестоящее руководство.

Данное сообщение сформировано и отправлено автоматически. Ответ на него не требуется.
```

**Условия отправки**: 
- Акты находятся на согласовании более 48 часов
- Пользователь уже получил напоминание (не менее 24 часов назад)
- Статус акта все еще "На согласовании"

---

#### Тип 3: Высшему руководству (эскалация)

**Тема письма**: `Эскалация: срыв сроков согласования актов в Praktis ID`

**Текст сообщения**:

```
Уважаемый(ая) [Имя Отчество высшего руководителя]!

Ставим вас в известность о следующем:
Сотрудник [Имя Отчество сотрудника, должность] не согласовал в установленные сроки 
акты на платформе Praktis ID.

Дата и время поступления документов сотруднику: [дата и время].

24 часа назад, [дата и время], автоматическое уведомление было направлено его 
непосредственному руководителю, [Имя Отчество руководителя, должность].

На сегодняшний день, [текущая дата], указанные акты остаются не согласованными, 
что может влиять на последующие процессы.

Данное сообщение является финальным уведомлением в рамках автоматической системы эскалации.

Данное сообщение сформировано и отправлено автоматически. Ответ на него не требуется.
```

**Условия отправки**: 
- Акты находятся на согласовании более 72 часов
- Руководитель уже получил уведомление (не менее 24 часов назад)
- Статус акта все еще "На согласовании"

---

### Временная шкала эскалации

```
0 часов    → Акты отправлены на согласование
24 часа    → Напоминание пользователю (Тип 1)
48 часов   → Уведомление непосредственному руководителю (Тип 2)
72 часа    → Эскалация высшему руководству (Тип 3)
```

**Примечание**: Все временные интервалы настраиваемы в админ-панели дашборда.
