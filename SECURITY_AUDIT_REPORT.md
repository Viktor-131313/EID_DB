## 🔴 КРИТИЧЕСКИЕ ПРОБЛЕМЫ

### 1. API ключ захардкожен в коде
**Файл:** `ID/backend/services/aikona-sync.js:24`  
**Код:**
```javascript
const AIKONA_API_KEY = 'f48941fd-ab51-4edd-b1f2-f202597c9920';
```
**Риск:** API ключ доступен всем, кто имеет доступ к репозиторию. Если репозиторий публичный или утечка произойдет, ключ может быть скомпрометирован.

**Рекомендация:**
- Переместить API ключ в переменные окружения: `process.env.AIKONA_API_KEY`
- Добавить `.env` в `.gitignore` (уже есть)
- Использовать секреты на хостинге (Render.com Environment Variables)

---

### 2. Пароль администратора захардкожен в коде фронтенда
**Файл:** `ID/frontend/src/components/AuthModal.js:13`  
**Код:**
```javascript
if (username === 'admin' && password === 'Admin2026!') {
```
**Риск:** Пароль доступен всем пользователям через исходный код фронтенда (можно увидеть в DevTools, при сборке). Аутентификация происходит на клиенте, что небезопасно.

**Рекомендация:**
- Реализовать серверную аутентификацию через API endpoint
- Использовать JWT токены или сессии
- Хранить хешированные пароли в базе данных (bcrypt)
- Минимизировать фронтенд код (не включать пароли в сборку)

## 🟠 ВЫСОКИЕ ПРОБЛЕМЫ

### 3. CORS разрешен для всех источников
**Файл:** `ID/backend/server.js:9`  
**Код:**
```javascript
app.use(cors());
```
**Риск:** Любой сайт может делать запросы к вашему API, что может привести к CSRF атакам или утечкам данных.

**Рекомендация:**
```javascript
app.use(cors({
  origin: process.env.ALLOWED_ORIGINS?.split(',') || ['http://localhost:3000'],
  credentials: true
}));
```

---

### 4. Использование innerHTML (потенциальная XSS)
**Файл:** `ID/frontend/src/utils/pdfExport.js:562`  
**Код:**
```javascript
info.innerHTML = `<strong>Сравнение с планеркой:</strong> ${oldDate} → ${newDate}`;
```
**Риск:** Если `oldDate` или `newDate` содержат пользовательский ввод, возможна XSS атака.

**Рекомендация:**
- Использовать `textContent` вместо `innerHTML` где возможно
- Санитизировать данные перед вставкой в HTML
- Использовать библиотеку для экранирования (например, DOMPurify)

---

### 5. Отсутствие Rate Limiting
**Файл:** `ID/backend/server.js`  
**Риск:** API может быть перегружен запросами (DoS атака), особенно эндпоинты аутентификации и создания данных.

**Рекомендация:**
- Установить `express-rate-limit`
- Ограничить количество запросов с одного IP
- Особенно важно для эндпоинтов аутентификации

---

### 6. Отсутствие CSRF защиты
**Файл:** `ID/backend/server.js`  
**Риск:** Подделка межсайтовых запросов может привести к неавторизованным действиям.

**Рекомендация:**
- Использовать `csurf` middleware (для сессий) или CSRF токены
- Если используется JWT, убедиться в правильной настройке CORS

## 🟡 СРЕДНИЕ ПРОБЛЕМЫ

### 7. Отсутствие защитных HTTP заголовков (Helmet.js)
**Файл:** `ID/backend/server.js`  
**Риск:** Отсутствие защитных заголовков может упростить некоторые виды атак.

**Рекомендация:**
```javascript
const helmet = require('helmet');
app.use(helmet());
```

---

### 8. Слишком большой лимит размера запроса (50MB)
**Файл:** `ID/backend/server.js:11-12`  
**Код:**
```javascript
app.use(express.json({ limit: '50mb' }));
app.use(express.urlencoded({ extended: true, limit: '50mb' }));
```
**Риск:** Может быть использовано для DoS атаки через большие запросы.

**Рекомендация:**
- Уменьшить лимит до необходимого минимума (например, 10MB для фото)
- Использовать streaming для больших файлов
- Валидировать размер файлов перед обработкой
