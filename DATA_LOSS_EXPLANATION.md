# ❌ Объяснение потери данных актов

## Что произошло:

1. ✅ Вы добавили объекты на продакшене
2. ✅ Вы добавили акты в объекты на продакшене
3. ❌ Вы скачали данные скриптом **ДО того, как акты были сохранены** или **когда они еще не были введены**
4. ❌ В скачанных файлах все акты были с `count: 0` и `total: 0` (пустые)
5. ❌ Эти пустые данные были закоммичены в git
6. ❌ При деплое Render.com перезаписал файлы на продакшене данными из git
7. ❌ Когда Render "проснулся", он использовал данные из git (с нулями)
8. ❌ **Все внесенные акты были потеряны**

## ⚠️ Важно понимать:

**Render.com при деплое всегда перезаписывает файлы данных из репозитория!**

Это означает:
- Если в git есть файлы с пустыми данными → они перезапишут реальные данные на продакшене
- Если в git есть файлы с реальными данными → они сохранятся при деплое

## ✅ Правильный процесс (на будущее):

### Шаг 1: Внесите данные на продакшене
- Добавьте объекты
- Внесите все акты
- **Подождите 1-2 минуты**, чтобы сервер точно сохранил данные
- Убедитесь, что данные отображаются корректно

### Шаг 2: Скачайте данные СРАЗУ ПОСЛЕ ввода
```bash
cd ID
node scripts/download-production-data.js
```

### Шаг 3: Проверьте скачанные данные
```bash
node scripts/check-act-counts.js
```

**Должны увидеть:**
```
✅ Объектов с данными: > 0
✅ Всего сгенерированных актов: > 0
```

**Если видите:**
```
❌ Все акты пустые (все значения = 0)
```
→ **НЕ коммитьте!** Внесите данные на продакшене заново и скачайте снова.

### Шаг 4: Закоммитьте данные
```bash
git add backend/data/*.json
git commit -m "Backup: Данные с актами с продакшена $(Get-Date -Format 'yyyy-MM-dd')"
git push
```

### Шаг 5: Теперь можно деплоить код
Только после того, как данные закоммичены, можно безопасно деплоить изменения кода.

## 🔍 Как проверить данные перед коммитом:

Используйте скрипт проверки:
```bash
node scripts/pre-commit-check.js
```

Он покажет:
- Количество объектов
- Количество актов
- Предупреждения, если данные пустые
