# 🚨 ВОССТАНОВЛЕНИЕ ДАННЫХ - СРОЧНО

## ❌ Что произошло:

Данные с продакшена были перезаписаны старыми данными из репозитория при деплое. В репозитории были только тестовые данные ("vbbbn", "сапава"), которые заменили ваши реальные данные на Render.com.

## 🔍 Варианты восстановления:

### 1. Проверьте Render.com Dashboard (срочно!)

**Откройте Render.com Dashboard:**
1. Зайдите на https://dashboard.render.com
2. Откройте ваш сервис (eid-praktis-id)
3. Найдите вкладку **"Shell"** или **"Logs"**
4. Попробуйте открыть Shell (если доступен)

**Если Shell доступен, выполните:**
```bash
cd /app/backend/data
ls -la *.json
cat objects.json
cat tasks.json
```

**Если файлы еще есть с реальными данными:**
```bash
# Скопируйте содержимое файлов
cat objects.json > /tmp/objects_backup.json
cat tasks.json > /tmp/tasks_backup.json
cat snapshots.json > /tmp/snapshots_backup.json
```

Или скопируйте содержимое вручную через интерфейс.

---

### 2. Проверьте Render Logs

Может быть в логах остались какие-то данные? Проверьте логи за последние часы.

---

### 3. Проверьте git reflog (маловероятно, но попробуйте)

```bash
cd ID
git reflog
git show <commit-hash>:backend/data/objects.json
```

---

## 📝 Что делать, если данные потеряны:

1. **Заново введите данные** через интерфейс на продакшене
2. **СРАЗУ после ввода** скачайте данные скриптом:
   ```bash
   node ID/scripts/download-production-data.js
   ```
3. **Проверьте файлы** в `ID/backend/data/`
4. **Закоммитьте** данные ОТДЕЛЬНО:
   ```bash
   cd ID
   git add backend/data/*.json
   git commit -m "Backup: Реальные данные с продакшена"
   git push
   ```

---

## ⚠️ ЧТО ДЕЛАТЬ В БУДУЩЕМ:

### ✅ ПРАВИЛЬНЫЙ процесс деплоя:

1. **ПЕРЕД любыми изменениями кода:**
   ```bash
   # Скачать данные с продакшена
   node ID/scripts/download-production-data.js
   ```

2. **Проверить, что данные скачались:**
   ```bash
   # Посмотреть размеры файлов - должны быть достаточно большими
   ls -lh ID/backend/data/*.json
   ```

3. **Ввести данные вручную, если нужно** (через интерфейс на продакшене)

4. **Скачать данные СНОВА:**
   ```bash
   node ID/scripts/download-production-data.js
   ```

5. **Закоммить данные ОТДЕЛЬНО от кода:**
   ```bash
   cd ID
   git add backend/data/*.json
   git commit -m "Backup: Данные с продакшена $(date +%Y-%m-%d)"
   git push
   ```

6. **Только ПОТОМ** делать изменения кода и деплоить

---

## 🔒 Рекомендации для безопасности данных:

1. **Делайте бэкапы перед КАЖДЫМ деплоем**
2. **Используйте git tags** для важных версий:
   ```bash
   git tag -a v1.0-with-data -m "Версия с данными"
   git push --tags
   ```
3. **Рассмотрите использование внешнего хранилища** (например, отдельный git репозиторий для данных)
4. **Проверяйте данные в staging окружении** перед деплоем на продакшн
